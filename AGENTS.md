# Repository Guidelines

## Project Structure & Module Organization

This repository is a TypeScript + Blockly web editor for Mindustry Mlog. Source files live in `src/`:

- `src/index.ts`, `src/index.html`, and `src/index.css` define the app shell, Blockly workspace, diagnostics panel, and UI styling.
- `src/appState.ts` holds app-level state shared across modules.
- `src/serialization.ts` handles workspace JSON serialization/deserialization and autosave.
- `src/blocks/` contains block registrations, Mindustry data, field helpers, vanilla block schemas, and custom Mlog sugar blocks.
- `src/mlog/generator.ts` converts Blockly workspaces into Mlog and emits diagnostics.
- `src/generators/javascript.ts` provides the JavaScript generator for the Blockly workspace.
- `src/toolbox.ts` defines toolbox categories and default blocks.
- `dist/` is generated by webpack; do not edit it manually.

## Build, Test, and Development Commands

- `npm install` installs dependencies from `package-lock.json`.
- `npm run start` launches webpack dev server and opens the editor locally.
- `npm run build` creates a production bundle in `dist/` and performs TypeScript compilation through `ts-loader`.

There is no committed automated test suite yet. For generator-specific checks, prefer small temporary Node scripts compiled with `npx tsc --project tsconfig.json --module commonjs --outDir .tmp-node`, then delete `.tmp-node` and any `.codex_*` files.

## Coding Style & Naming Conventions

Use TypeScript with 2-space indentation and semicolons, matching existing files. Prefer `const` unless reassignment is required. Use camelCase for variables/functions, PascalCase for interfaces/types, and `mlog_*` prefixes for custom Blockly block types. Keep user-facing block labels mostly Chinese, but keep established programming keywords such as `if`, `while`, `for`, `when`, `fun`, `call`, and `return` in English. Do not translate generated in-game Mlog tokens.

## Testing Guidelines

Run `npm run build` before handing off changes. When changing `src/mlog/generator.ts`, include at least one focused generator sanity check covering the changed behavior. When changing Blockly shapes or mutators, verify serialization/deserialization and generated Mlog output. Keep temporary validation artifacts out of the repository.

## Commit & Pull Request Guidelines

The repository has Git history (branch `main`), so use clear imperative commit messages such as `Add fun diagnostics定位` or `Fix when case mutator generation`. Pull requests should include a concise summary, affected files or features, screenshots/GIFs for UI changes, and the exact validation commands run.

## Agent-Specific Instructions

Do not add compatibility for unrelated `MlogSuger`/`MlogSugar` projects. Preserve support for vanilla Mindustry logic blocks except original `jump`, and keep vanilla categories/dropdowns aligned with Mindustry source data. Prefer minimal, focused edits and avoid modifying generated `dist/` unless explicitly requested.
